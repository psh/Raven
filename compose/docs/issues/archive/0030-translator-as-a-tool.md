# XML translator as a tool

## Question

How is the sample's XML parsing and translator extracted for reuse: a shared module, a command-line tool, a Gradle task, or several? Decide where the private cinterop goes, how `<Include>` is followed across files (one set of functions per file), how output files are named and laid out, and whether the translator runs headless without a window.

## Resolution

- **Form**:
  - A library module, **`compose-raven-xml`**, takes the parse adapter, the private cinterop and `translate()` out of `samples/xml-translator`, which then depends on it.
  - A command-line tool, **`raven-xml2compose`**, is a Kotlin/Native executable built on that module, one per host.
  - A Gradle task can't load a Kotlin/Native library on Gradle's JVM, so it would have to run the native tool. It goes to the fog (Build-time XML translation).
- **Cinterop and Raven**: `ravenxml.def` moves into `compose-raven-xml` as an `implementation` detail, so no Raven type appears in its API. It still has no `staticLibraries`, because `libraven.a` comes through `raven-native`. The tool starts Raven **headless** (`Rinit_ex` with the null backend and `headless = true`, no window), translates, and shuts down. The sample keeps using the Raven instance its app already runs.
- **`<Include>` across files**: `Source` resolves relative to the including file. Each XML file becomes one Kotlin file. A declarations-only file (`<Widgets>` root) yields its composables. A file whose root is an element also yields a composable named after the file (`header.xml` becomes `@Composable fun Header()`), and including it becomes a call to `Header()`. A file included from several places is translated once. An include cycle is an error that reports the chain. The single-pane sample keeps `<Include>` as a TODO.
- **Usage**: `raven-xml2compose ui/ --out src/nativeMain/kotlin/app/ui --package app.ui [--main main.xml] [--werror]`.
  - Inputs are files or directories of `.xml`.
  - Output files are the PascalCase form of the XML file name (`now_playing.xml` becomes `NowPlaying.kt`), in `--package`.
  - `main()` (as `singleWindowApplication(...)`) is emitted only for the `<Window>` root named with `--main`. Other `<Window>` roots become plain composables with a warning.
  - Each generated file starts with `// Generated by raven-xml2compose from <path>. Do not edit.`, and the tool overwrites only files that start with that header, so hand-written files are never lost.
  - Warnings go to stderr as `file:line:column: message`. The exit code is non-zero on errors (bad XML, include cycles) and zero with warnings only. `--werror` makes warnings fail.
- **Tests**: the unit tests on `XmlElement` trees move into `compose-raven-xml`. New tests run the tool's file handling (include resolution, naming, overwrite refusal, exit codes) on fixture directories, with Raven started headless once per test.
