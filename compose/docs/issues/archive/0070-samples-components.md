# samples/components

Port Raven's `examples/components`: cards, badges and stats, which the C example declares as XML
`<Widget>`s, become ordinary composables, and "Add a card" adds one. Spec:
[10. Samples](../../spec.md#10-samples),
[8: Surface, FlowRow and Expander](../../spec.md#phase-2-surface-flowrow-and-expander).

**Depends on:** [Surface, FlowRow and Expander](0064-surface-flowrow-and-expander.md),
[Window: WindowState and its parameters](0086-window-windowstate-and-its-parameters.md),
[Modifier.appearTransition](0088-modifier-appeartransition.md).

## Deliverables

- [x] `samples/components` with the C example's look, 760 by 560: the dashboard title and "Add a
      card", the cards in a `FlowRow` inside a `VerticalScroll`, the status line, and the source
      pane in an `Expander`.
- [x] The sample's own composables, built on `Surface`, `FlowRow`, `Row` and `Text`:
      `Card(title, badge, wide, footer: @Composable RowScope.() -> Unit, content)` (the `footer`
      slot replaces `Into="footer"`), `Stat(label, value, trend)`, `Badge(text, color)` and
      `PersonRow(name, role, online)`.
- [x] `<Repeat>`, `<ForEach>` and `{...}` expressions become Kotlin loops and string templates.
- [x] Added cards are app state, a `mutableStateListOf<CardData>()` shown with `key(card.id)`:
      "Add a card" appends the next title and stats as the C code does, and a card's "Remove"
      removes it from the list.
- [x] The source pane shows the Kotlin call that composes the last card added, generated by the
      sample from its `CardData`, in a read-only `CodeEditor(language = "Kotlin")` under "The Kotlin
      of the cards added".
- [x] The cards' transitions: `Modifier.appearTransition(Pop, delay)` for the first three, `Drop`
      for added ones.
- [x] The status line starts with a hint and reports each add and remove.
- [x] The C example's minimum window size, as `minimumSize`.
- [x] Runs from Gradle like `samples/hello`, documented in `compose/README.md`.
- [x] A headless test: "Add a card" adds a card with the next title and shows its Kotlin, and its
      "Remove" takes it away.

## Gaps

None: the card transitions came into phase 2 with [Modifier.appearTransition](0088-modifier-appeartransition.md)
([ADR 0001](../../adr/0001-phase-split-after-the-phase-2-sample-gaps.md)).

Building an XML document from code and the registry of declared `<Widget>` tags have no
counterpart, since a card is data and a composable, and are no gaps
([The components sample's source pane](0078-the-components-samples-source-pane.md)).

## Resolution

Done and run on macOS. `./gradlew build allTests` passes: 282 tests, 3 of them the sample's
`ComponentsTest`.

- **The sample** (`raven.sample.components`, `Main.kt`): `main` is `application { Window(state =
  rememberWindowState(size = DpSize(760.dp, 560.dp)), title = "Raven - components", minimumSize =
  DpSize(520.dp, 400.dp)) { Components() } }`. `Components` is a `VerticalScroll` of a 16 dp-padded
  Column with a 12 dp gap. It holds a Row with the 24 sp "Dashboard" (weighted) and `Button` "Add a
  card"; the cards in a `FlowRow` (`spacedBy(12.dp)`); the status `Text`; and an `Expander` "The
  Kotlin of the cards added", open at first, around a read-only 150 dp
  `CodeEditor(language = "Kotlin")`. The executable is `components.kexe`.
- **The sample's own composables**, private to it:
  - `Card(title, badge, wide, modifier, footer: @Composable RowScope.() -> Unit, content:
    @Composable ColumnScope.() -> Unit)` is a `Surface(shape = RoundedCornerShape(14.dp))`, 220 dp
    wide or 452 dp when `wide`. It shows the title (16 sp) and its badge (red for "hot", else
    blue), a `HorizontalDivider`, the content, and the footer Row at the end.
  - The `modifier` parameter, which the ticket's list doesn't name, carries each card's
    `appearTransition`.
  - `Stat`, `Badge` (a `CircleShape` Surface with white 11 sp capitals) and `PersonRow` follow
    `widgets.xml` and the XML's `Row`.
- **Loops and templates**: the Servers card's `<Repeat>` is `repeat(4) { i -> }` and its
  `<ForEach>` is `listOf("paris", "tokyo", "oslo").forEachIndexed { n, city -> }`, with the values
  as string templates.
- **Added cards** are a `mutableStateListOf<CardData>()`, shown with `key(card.id)` after the XML's
  three cards.
  - `cardData(index)` gives the C code's title (`Builds`, `Tickets`, `Reviews` and `Deploys`, in
    turn) and stats (`3 + (index * 7 + i * 11) % 40`, with trends -1 and 1).
  - "Remove", a `TextButton` in the card's footer, removes that card.
  - `cardSource(card)` writes the Kotlin call that composes the card, and the source pane shows
    it. Before the first add the pane shows `// press "Add a card"`.
- **Transitions**: `Pop` for the first three cards, at 0, 60 and 120 ms, and `Drop` for added
  ones.
- **Status line**:
  - It starts with a hint.
  - An add shows the C example's "1 card added..." and "Several cards added..." lines, with Kotlin
    in place of C.
  - A remove shows `"Builds" removed.`
  - The footer buttons (Details, Restart all and Logs) show a line of their own, as the C
    example's `card.details` does.
- **Readings and deviations**:
  - The C example's "Declared tags" status has no counterpart (0078), so the status starts with
    a hint.
  - **`Opacity="0.6"`** on the muted labels has no compose-raven counterpart: there is no
    `Modifier.alpha`, and the spec has opacity only for windows and phase 3's `fadeOut`. The muted
    labels use `Color.Gray`, which reads the same on light and dark themes. This isn't recorded
    as a gap, since the look is kept.
  - The button styles map as the translator maps them: `Style="Primary"` is `Button`, the default
    style is `OutlinedButton`, and `Flat` is `TextButton`.
  - `main.c` never loads `theme.xml`, so the port doesn't either.
- **README**: how to run `samples/components`.
- **Checked by eye** on macOS, from a capture of the running window: the dashboard title and "Add a
  card", the Sales, Team and Servers cards wrapping in the FlowRow with their coloured badges and
  stats, the hint, and the open source pane.
- **Tests** (`ComponentsTest`):
  - the three cards, the Servers loops and the hint are there, the pane shows the comment, and
    there is no "Remove";
  - "Add a card" adds "Builds" with its stats and shows its Kotlin; "Remove" takes it away and the
    status reports it; a second add gives "Tickets" and the "Several cards" status;
  - `cardData` gives the C example's titles, values and trends.
